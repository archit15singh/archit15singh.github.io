Most agent "research" does the same thing. It tours a field, writes a long report, and never tells you what you would work tomorrow. Stars get ranked. Vendors get taxonomied. Search never stops.

I built **[Vital Few](https://github.com/archit15singh/vital-few)** for the opposite job: name an object, compress the field, compete, commit, stop.

Two files. No runtime. You copy `SKILL.md` and `LOOP.md` into the agent's skills directory and fire it when you want a field compressed, not toured. The spec is the loop. The runbook is the skill. That is the whole product.

This post is the design: what it is, why stop is the load-bearing part, and what one pass looks like on a real field.

---

## The problem is search that cannot commit

Memori is about *state that survives sessions*. Luffy is about *a review you can audit*. Hard constraints belong in code because a model will not enforce a rule it only "understands".

There is a fourth failure, and I kept hitting it while I was trying to pick what to build next.

Give an agent a terse pointer (a name, a URL, "things like X") and it will produce a tour. Twenty siblings. A vendor taxonomy. A weighted score that hides the tradeoff. Then another search, because the last one did not feel done.

The useful output was never the tour. It was the cut: which objects actually distinguish the field, which hypotheses disagree, and which one item you would start tomorrow.

Juran already had a name for that cut. He hung Pareto's name on it, then spent a 1974 mea culpa walking it back: the *vital few* versus the *useful many*. The many are not junk. You name them once and leave them. You work the few.

Agents do the inverse. They expand the tail.

## What Vital Few is (and is not)

One line: an agent skill that turns a terse pointer into a reusable frame and a top-k you would work, then stops.

```text
name → instance → siblings → rank
    → ontology → frame → explode → cca
    → hypothesis-rank → top-k → extract loop
```

**In.** A name, a URL, or "things like X".

**Out.** Nine things, in order:

1. Named object + one-line job
2. Primary instance (is / is not / limits) from the owner's page
3. Sibling front: the non-dominated set, plus a named tail
4. Ontology (3–7 entities) and a 2–4 genus cut
5. An imported frame with sourced axes, not a vibe
6. A list after cross-consistency analysis
7. Competing hypotheses that actually disagree
8. Top-k taken from the front, plus an item-1 witness
9. The loop itself, named, so you can run it on a different object

**Is not.** A Deep Research writer. A scanner. A product with a runtime. An implementation of the top-k. If you already know the API, or you are fixing one file, do not fire it.

The fail-closed rules are as important as the steps. No primary source for the instance? Stop after step 2 and say so. No sourced frame? Skip the explode and emit the sibling front only. Do not invent axes.

## Rank geometry, not a vibe

The loop is not "think harder". Each move has a source, and the sources are why I trust the stop.

| Move | What it does |
|---|---|
| Vital-few sweep | Keep the non-dominated set on the load-bearing columns. Name the tail once. [Juran 1974](https://www.juran.com/wp-content/uploads/2021/03/The-Non-Pareto-Principle-1974.pdf). |
| One extra sibling pass | Search the *job*, not the brand. One snowball. Zwicky morphological box, Wohlin. |
| Cross-consistency | Kill cells that contradict the instance, the first cut, or each other. Empty is allowed. Contradiction is not. |
| Empirical rank | Hypotheses that disagree. Each vote cites a published measurement. Chamberlin 1890, Platt 1964, Pugh +/−/S against a datum. |
| Commit | k from the front. Simon 1955: satisficing. Then stop. |

Star counts are not a witness. One weighted score at the collate step is a lie: the columns *were* the sweep, and the score hid the tradeoff.

The aspiration check is four booleans, not "looks done":

1. A framing sentence exists and names the ontology.
2. Top-k is from the front. k is not N.
3. Item-1 witness: would you start work on item 1 tomorrow with only that sentence and this list? Written `yes` plus one line, or `no`.
4. No further search is queued.

If 3 is `no`, you get one recut of k or of item 1. Then you stop anyway. Recursion is bounded candidate generation, not a generational optimizer. Running the candidates is the work *after* this loop.

That last sentence is the whole point. I have watched agents treat ranking as a warm-up for more ranking. Vital Few makes that a fail.

## One pass: "anthropic autonomous vulnerability patcher"

The worked example in the repo is the pointer I actually used.

**Object.** Defending Code Reference Harness, and the class it sits in: closed-loop CRS.

**Job.** Autonomous recon → find → verify → patch, with a witness that is not a paragraph.

The instance is [anthropics/defending-code-reference-harness](https://github.com/anthropics/defending-code-reference-harness). Unmaintained Apache-2.0 reference. C/C++ memory bugs, Docker + ASAN, gVisor. The find agent emits a crashing input. A grader in a fresh container sees only PoC bytes. Patch ladder: build, PoC gone, tests, re-attack. A human still merges.

Not Claude Security (hosted). Not a general SAST wrapper.

Siblings ranked on *runnable OSS that closes find → prove → patch*, not stars: FuzzingBrain / OSS-CRS, the Anthropic reference, [google/mantis](https://github.com/google/mantis), [Visa VVAH](https://github.com/visa/visa-vulnerability-agentic-harness), [Capital One VulnHunter](https://github.com/capitalone/VulnHunter), [Hadrian OpenHack](https://github.com/hadriansecurity/OpenHack). Closed systems stay in the table and get marked closed. They are not ranked as clones you can run.

**First cut.** Does a finding require an executable witness, and does a patch have to survive an independent check?

**Entities.** Target, threat model, witness, trust split, fix gate. If you can drop an entity and still tell two instances apart, it was never an entity.

The frame I imported is Stanford Symbolic Systems: philosophical analysis, formal methods, computational methods, empirical cognitive science. [Sourced](https://symsys.stanford.edu/undergraduates/major-policies-requirements/core-requirements), not invented that afternoon.

Hypotheses that disagree (the useful ones):

| | Claim |
|---|---|
| H1 Formalization | Next leap is proof-like witnesses and fix-gates |
| H2 Communication | Bottleneck is symbols a human can merge |
| H3 Architecture | Load-bearing invention is the trust split |
| H5 Hybrid is the object | Neural finder + symbolic grader *is* the system |

H5 is the frame. Rank projects by H1 ∧ H2 ∧ H3. A philosophy-first hypothesis that does not ship gets demoted to vocabulary. That is CCA doing work: cells that cannot coexist with the instance get dropped before anything is numbered.

**Top-k**, from the front:

1. Witness as a checkable proof object
2. Threat model as compiled common ground
3. Public-language / bytes-only as the computational-level claim
4. Finding-as-communication (the merge bottleneck)
5. Patch as making the vulnerability uninhabited

Item-1 witness: yes. Tomorrow I would start by making the finding a proof object the grader can reject without reading the finder's inner story.

Then extract the loop: strip the vuln nouns. What remains is Vital Few. That is step 11. Terminal. Do not recurse.

## Why this sits next to Memori and Luffy

Memori stores what the agent learned. Luffy exports the loop so you can audit a review. Vital Few is the cut *before* you spend a week building the wrong sibling.

All three are the same thesis I keep writing down: probabilistic systems need a deterministic surround. Memory, constraints, traces, and now a stop condition that is a check, not a feeling.

The surround here is procedural, not a database. `LOOP.md` is the spec. `SKILL.md` is the runbook with YAML frontmatter `name: vital-few`. MIT. Clone it, copy two files, point the agent at a pointer.

```bash
git clone https://github.com/archit15singh/vital-few.git
```

Do not fire it to implement the top-k. That is the next loop. This one is finished when you would start item 1 tomorrow, and you have queued no further search.
